## Линза: причина и результат

Изменение размера ручкой выполнялось синхронно на UI-потоке на каждое событие мыши:

1. прозрачные окна рамки и пунктира источника (WPF `AllowsTransparency`) меняли размер дважды — `SetWindowPos` в пикселях и
   затем `Width`/`Height` в DIP с другим округлением; каждое изменение размера layered-окна — синхронная полная перерисовка
   и копирование буфера окна (23 и 14 мс на шаг у окна ~1900×1350);
2. неизменный стиль рамки применялся заново: новые `DropShadowEffect`, кисти, регион окна, повторное размещение рамки;
3. окно Magnification API меняло размер с перерисовкой (`MoveWindow(…, true)`, ~10 мс), фон стирался, кадр лупы обновлялся
   дважды за кадр (таймер и изменение геометрии);
4. события мыши (500–1000 Гц) применялись все подряд — устаревшие положения копились в очереди.

Исправлено: смещения ручки объединяются до одного применения перед кадром (`CompositionTarget.Rendering`, смещение
абсолютное — последнее применяется всегда, в том числе при отпускании); прозрачные окна выделяются с запасом шагами 256 px
(`LayeredWindowSize`, не за край монитора), окно лупы и хозяин — с запасом только во время перетаскивания (видимую форму
задаёт регион; после отпускания размер точный); стиль не применяется повторно; лупа без синхронной перерисовки и стирания,
новый источник ставится сразу, повторный кадр в том же интервале пропускается. Качество и частота обновления не менялись.

Замер `LensResizeBenchmark` (переменная `BACKPACK_LENS_BENCH`, монитор 2560×1600, 150 %, источник показан, тень):

| | до | после (2 прогона) |
|---|---|---|
| шаг изменения размера, среднее / медиана / p95 | 55,2 / 53,7 / 70,5 мс | 21,6–22,8 / 20,3 / 37–38 мс |
| выделения на шаг | 35,6 КБ | 16,0 КБ |
| 1000 событий ~1000 Гц: обработаны за / отставание после потока | 47,9 с / 360 мс | 11,0 с / 75–82 мс |

Оставшиеся ~20 мс: перемещение трёх прозрачных окон ручек, захват кадра лупы (`MagSetWindowSource`), отрисовка; редкие
пики — перевыделение окна при переходе через шаг запаса.

## Проверки

- Модульные тесты (Release): Core 115/115, Visual 648/648. Новые: `Phase4JTests` (автозапуск во временном разделе реестра:
  включение/выключение, другая копия, перенесённая папка и устаревшая команда, отключение в Windows, разбор команды,

  значения и резервные копии), `LensResizeTests` (объединение событий, шаги запаса, точный размер после отпускания).

  `--autostart` — процесс в трее без главного окна; повторный `--autostart` — выход с кодом 0, один экземпляр; повторный
  обычный запуск — выход, первый показывает окно; переключатель «Start with Windows» записывает и удаляет значение `Run`
  этой копии и показывает состояние — 14 PASS. Настоящие данные пользователя (`%APPDATA%\Backpack`) и его запущенный
  Backpack не трогались.
- Пакет `Backpack-0.4.0-preview.7-win-x64.zip` (89,6 МБ, SHA-256 `28ff1ecf…568d`): `verify-package.ps1 -SelfTestUi` —
  51 PASS, 0 FAIL; самопроверка интерфейса 419 шагов (с переключателем автозапуска в своём разделе реестра, плагинами
  «Линза», «Фокус», «Увеличение у курсора», «Рисование», «Индикатор раскладки», таймер).
- Иллюстрации README и справки отрисованы из распакованного пакета.

Не проверено: вход в Windows с настоящим автозапуском (перезагрузка), живое изменение размера линзы рукой на нескольких
мониторах с разным DPI (логика переноса между мониторами покрыта прежними тестами, запас окна ограничен краем монитора).
