# KeyOverlay — Phase 2F: живая линза и временное рисование

**Дата:** 2026-10-29
**Код:** `lab/src/KeyOverlay.Visual/Presentation/` (`PresentationModes.cs`, `PresentationController.cs`, `LiveLens.cs`, `InteractiveWindows.cs`, `PresentationNative.cs`); связывание — `Lab.App/App.xaml.cs`.

## 1. Реализовано

### 1.1 Выбор механизма линзы

Рассмотрены по документации Windows:

| Механизм | Плюсы | Минусы для KeyOverlay |
|---|---|---|
| **Magnification API** (`Magnification.dll`, элемент Magnifier, `MagSetWindowSource`/`MagSetWindowTransform`/`MagSetWindowFilterList`) | живое изображение системой, увеличение матрицей, **исключение собственных окон** списком, без захвата в файлы, работает в обычном процессе x64 без uiAccess | только процесс той же разрядности (x64 — подходит); элемент — дочернее Win32-окно (не WPF), обновление по таймеру |
| Windows.Graphics.Capture | современный, GPU | WinRT/Direct3D-интероп в WPF, исключение своих окон через `WDA_EXCLUDEFROMCAPTURE`, жёлтая рамка захвата в части версий; заметно сложнее и тяжелее |
| BitBlt/PrintWindow по таймеру | просто | копирование пикселей экрана в память процесса на каждый кадр, рекурсия без исключений, высокая нагрузка |

Выбран **Magnification API**. Хозяин линзы — собственное Win32-окно (layered, `WS_EX_TRANSPARENT`, `WS_EX_NOACTIVATE`, `WS_EX_TOOLWINDOW`, topmost) со скруглённой областью (`SetWindowRgn`); внутри — элемент Magnifier с матрицей увеличения; рамка и тень — отдельное WPF-окно no-activate/click-through поверх хозяина. Хозяин, рамка и окно рисования исключены из источника (`MW_FILTERMODE_EXCLUDE`) — рекурсивного изображения нет. Источник — центр выбранной области, уменьшенный в «увеличение» раз; обновление — таймер 16 мс только пока линза открыта. Пиксели процесс не читает: их отрисовывает система.

### 1.2 Технический прототип

Самопроверка `KeyOverlay.exe --lab --selftest-ui` открывает настоящую линзу (увеличение 1.5) на области 240×135 у верхнего левого угла рабочей области основного монитора на 0.6 с: **`lens status Live, frames 23, source failures 0, host window yes`**, затем закрывает и проверяет `MagUninitialize` (`lens released`). Это подтверждает работу API в этом процессе (инициализация, окно, источник принимается, обновления идут). Содержимое на экране программой не снималось и не просматривалось — **«живость» изображения визуально не подтверждена мной**; это пункт ручной проверки (§5).

### 1.3 Поведение линзы

1. Горячая клавиша (по умолчанию Ctrl+Alt+Shift+Z) или «Запустить» на «Главной» → окно выбора на мониторе под указателем (лёгкое затемнение, подсказка). Протягивание — область; щелчок без протягивания (< 12 DIP) — размер по умолчанию вокруг точки; Esc или правая кнопка — отмена.
2. Линза на месте выбранной области: скруглённая рамка с тенью, увеличенная живая середина.
3. Режим только просмотра: хозяин и рамка click-through и no-activate; клик проходит к окну под линзой. Совпадение клика с увеличенным элементом не обещается; преобразования и инжекции ввода нет.
4. Закрытие: Esc (наблюдение за вводом основного источника, без подавления), повторная команда, таймер (по умолчанию 15 с; 0 — без таймера), скрытие отображения, блокировка/смена рабочего стола/сон, выход.
5. Источник недоступен (`MagSetWindowSource` = FALSE): элемент скрывается, рамка пишет «Экран сейчас недоступен для линзы» — устаревший кадр не выдаётся за живой.
6. Настройки (`app.json`): увеличение 1.1–4, размер по умолчанию, скругление, толщина и цвет рамки, тень, длительность, горячая клавиша.
7. DPI и координаты: всё в физических пикселях (процесс Per-Monitor V2); монитор и масштаб — `MonitorFromPoint` + `GetDpiForMonitor`; отрицательные координаты поддерживаются (`PixelRect`, тест); область ограничивается монитором.

### 1.4 Временное рисование

Окно на весь монитор под указателем; фон с альфой 1/255 (получает мышь, рабочий стол виден и живой); не в Alt+Tab (`WS_EX_TOOLWINDOW`).

- Инструменты: свободная линия, прямая, стрелка, прямоугольник, эллипс; 6 цветов, прозрачность (полная/60 %), толщина 1–40, сплошная/штриховая/пунктирная; отмена (Ctrl+Z), повтор (Ctrl+Y), очистка (отменяемая).
- Исчезновение: через N секунд (плавно удаляется и выпадает из истории) или «до выхода»; по умолчанию из настроек.
- Компактная панель сверху по центру; **радиальное меню** (8 секторов: 5 инструментов, следующий цвет, отмена, очистка; центр — закрыть) вокруг указателя, у края экрана сдвигается внутрь целиком. Выбор — щелчком; Esc, щелчок в центре или повторная горячая клавиша — закрыть без выбора. Отпускание горячей клавиши ничего не делает (`RegisterHotKey` срабатывает один раз при нажатии) — меню открыто до выбора или отмены.
- Рисунки не сохраняются; экран не записывается.

### 1.5 Состояния и выход

`PresentationModes` — чистая функция переходов (Normal, выбор области, линза, рисование, радиальное меню):

| Совместно | Правило |
|---|---|
| линза + рисование | да (линза только показывает, рисунок поверх) |
| выбор области + рисование | рисование становится click-through/no-activate на время выбора и возвращается после |
| выбор + линза | новая линза заменяет прежнюю; повторная команда во время выбора — отмена, при открытой линзе — закрытие |
| радиальное меню | только в рисовании (команда в другом состоянии включает рисование) |

Esc снимает один слой: меню → выбор → рисование → линза (из любого состояния ≤ 4 нажатия до обычного режима — тест на все 12 допустимых состояний × 8 команд). Esc приходит из окна рисования и из наблюдения за вводом — повтор в 200 мс считается одним нажатием. Скрытие отображения и потеря контекста вызывают `ExitAll`. Выход из режима **закрывает** окна режима (не прячет) — невидимого перехвата мыши не остаётся (`AnyWindowCapturesMouse == false`, `Hwnd == 0`, тесты).

## 2. Установленные причины ошибок

Ошибок прежнего кода в этой области нет (функции новые). Найдено при тестировании: повторная команда линзы при открытой линзе по правилам закрывает её — тест был составлен неверно и исправлен (правило не менялось).

## 3. Гипотезы

- Поведение линзы над окнами с правами администратора и над защищённым содержимым (DRM-видео, `WDA_EXCLUDEFROMCAPTURE`): по документации система не отдаёт такие пиксели; ожидается чёрная область или «недоступно». Не проверено.
- Частота обновления ~38 кадров/с в самопроверке (23 за 0.6 с при занятом UI-потоке); при обычной работе ожидается ближе к 60.
- Линза на мониторах с разным DPI при выделении через границу мониторов: область ограничивается монитором, где начат выбор.

## 5. Подготовленные, но не выполненные ручные проверки

1. **Живая линза.** Запустить KeyOverlay, открыть видео или анимированную страницу, Ctrl+Alt+Shift+Z, выделить область с движением → движение в линзе продолжается, увеличено; щелчок по линзе попадает в окно под ней (например, ставит курсор в Блокноте под линзой); Esc закрывает; таймер 15 с закрывает.
2. **Рекурсия.** Выделить область, в которой окажется сама линза при повторном выделении рядом — в линзе не видно её рамки.
3. **DPI и края.** Два монитора (в т. ч. слева от основного, отрицательные координаты) и масштаб 125–200 % (настраивает владелец): выделение у края, линза в границах монитора.
4. **Недоступный источник.** Открыть линзу и заблокировать компьютер (Win+L — вручную владельцем): после разблокировки линзы нет (закрыта при смене контекста).
5. **Рисование.** Ctrl+Alt+Shift+D: все инструменты, цвета, штрихи; Ctrl+Z/Y; «⏱» — исчезновение; Esc — выход; после выхода щелчки по рабочему столу работают.
6. **Радиальное меню.** Ctrl+Alt+Shift+R у каждого края и в углу экрана; выбор мышью; Esc; повторная клавиша.
7. **Скрытие во время режима.** Рисование + линза → Ctrl+Alt+Shift+O → оба закрыты, рабочий стол доступен.

## 6. Ограничения и блокеры

- Визуальная «живость» и качество увеличения не подтверждены на экране (§1.2, §5.1).
- Линза — только просмотр; клик по увеличенному изображению не переносится на увеличенный элемент (сознательно).
- Окно рисования — на одном мониторе (под указателем при включении).
- Esc для линзы приходит через наблюдение за вводом основного источника: если источник не получает Esc (например, фокус в окне с более высоким уровнем целостности), закрыть линзу можно повторной горячей клавишей или таймером.
- Magnification API помечен Microsoft как поддерживаемый, но не развивается; при проблемах на будущих версиях Windows — переход на Windows.Graphics.Capture.
