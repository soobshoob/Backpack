## Реализовано

| Область | Что сделано |
|---|---|
| Автомат приватности | `Core/Privacy/PrivacyGate.cs`: состояния Allowed / Checking / Protected / Unknown, причины (поле пароля, приложение из списка, проверка, нет данных, таймаут). Версия контекста растёт при каждой смене фокуса; результат старой версии игнорируется; таймаут 400 мс → «нет данных». Фильтр стоит **до** `DisplayModel` (`LabController.ApplyToDisplay`) — оверлей, будущая история и плагины (`VisibleTransition`) получают только прошедшее. |
| Правила скрытия | При закрытом показе отбрасываются Down и Up всех клавиш (модификаторы и сочетания, Ctrl+V тоже); нет буфера и воспроизведения. Клавиши, удерживаемые в момент закрытия или нажатые при закрытом показе, остаются скрытыми до своего отпускания (показ возобновляется на новом Down). Кнопки мыши не скрываются (не набираемый текст) — решение задокументировано. Esc наблюдается всегда (выход из инструментов), но не показывается. |
| Очистка | Закрытие → `Display.Clear()` и `Presenter.Clear()` во всех окнах оверлея: кейкапы, анимации исчезновения, счётчики нажатий; демо-пример тоже останавливается. Вторая линия: `OverlayWindow.Refresh` при закрытом показе передаёт только кнопки мыши. |
| Источник фокуса | `Win32/FocusPrivacySource.cs`: поток с WinEvent `EVENT_OBJECT_FOCUS` и `EVENT_SYSTEM_FOREGROUND` (только атомарный счётчик), **плюс** подписка на событие фокуса UI Automation (`App/UiaFocusEvents.cs`, регистрация вне UI-потока). Один рабочий MTA-поток UIA: `GetFocusedElement` → `GetCurrentPropertyValueEx(UIA_IsPasswordPropertyId, ignoreDefaultValue: TRUE)` — отсутствие свойства (ReservedNotSupportedValue) ≠ false. Value, TextPattern, Name, буфер обмена, заголовки окон не читаются. Запросы коалесцируются (одна проверка за раз, только последняя версия) — зависший провайдер не порождает очередь задач. |
| Перед кадром | `SyncPrivacyContext` в начале каждой порции доставки: сравнение атомарного счётчика и окна с фокусом клавиатуры (`GetGUIThreadInfo`) — ввод после замеченной смены фокуса не применяется до решения. |
| Устойчивость ответа | Разрешающий ответ подтверждается второй пробой через 80 мс (показ всё это время закрыт); разрешающий ответ отбрасывается, если фокус сменился во время пробы; запрещающий ответ той же версии перепроверяется (120/400/1200 мс). |
| Настройки и статус | app.json v3 `privacy` (включено, значок замка, список `*.exe`). Карточка «Динамическая приватность» в «Настройках приложения»: переключатель, значок, текущее состояние, добавление/удаление приложений, ограничения, ссылка на ручное скрытие (дублирующей функции нет). Значок на оверлее: замок + «Защищённое поле» / «Проверка» / «Нет данных» / «Скрыто для этого приложения», без количества и длины; не пишет «пароль обнаружен» при неизвестном состоянии. |
| Мониторы | `Visual/Windows/Monitors.cs`: перечисление (`EnumDisplayMonitors`, устойчивый ID — путь интерфейса устройства из `EnumDisplayDevices(EDD_GET_DEVICE_INTERFACE_NAME)`, запасной — имя адаптера), `MonitorResolver` (основной / выбранный / несколько / под курсором, fallback на основной с перечнем отсутствующих), геометрия «DIP рабочей области монитора → физические пиксели», `PhysicalPlacement` (SetWindowPos + повтор после `DpiChanged`). |
| Оверлей на нескольких мониторах | `App.LayoutOverlays`: одно окно `OverlayWindow` на монитор, одна модель отображения и один источник ввода; системные уведомления принимает только первое окно (оно не пересоздаётся). «Под курсором» — таймер 120 мс переносит окно без пересоздания (нет дублей, удержания и анимации продолжаются). WM_DISPLAYCHANGE и SPI_SETWORKAREA → повторное перечисление. |
| Индикатор раскладки | `LayoutIndicatorController`: окно на каждый целевой монитор, одна логика показа и срока; наследует мониторы кейкапов или имеет собственный выбор; положение — в DIP рабочей области своего монитора. |
| Формат | settings v5 (`displays`: keycaps, indicator с `inherit`), v1–v4 читаются; схема `docs/settings/backpack-settings.schema.json` (`$id` …-5), схема профиля ссылается на неё. На другом компьютере отсутствующий монитор → основной, страница «Положение и мониторы» показывает «“Имя” не подключён…». |
| Кейкапы | «Символ + подпись» — одна группа, центрированная в области подписи во всех рендерах (а не символ у верхнего края и текст у нижнего); метка R/Num — отдельный элемент, группу не сдвигает. Объёмный рендер: боковины — выпуклые оболочки (нет «бабочек» и щелей у выреза Enter), кромки основания, заслонённые самим корпусом, не рисуются (`Occluded` по лучу взгляда), запас по вертикали под обводку. Безопасная область Enter — справа от выреза; подпись движется вместе с верхней гранью. Laptop: тень больше не обрезается на 1 DIP. |

## Установленные причины

- **Дефект Enter (172608).** (1) У внутреннего угла выреза контуры основания и верхней грани скруглены разными радиусами; боковой четырёхугольник между ними становился самопересекающимся, и при объединении Nonzero оставались щели. (2) Нижняя кромка стенки выреза (u = ширина выреза) рисовалась как видимая, хотя в проекции её заслоняет корпус левой части клавиши — отсюда наклонная линия поверх грани. Сначала проверил гипотезу «закрыта верхней гранью» — не подтвердилась на крупном рендере; правильный критерий — заслонение корпусом вдоль луча взгляда.
- **Смещённые подписи (172703).** Общий код раскладки подписи ставил символ `VerticalAlignment.Top`, текст `Bottom`, у модификаторов — `Right`.
- **WPF не порождает WinEvent фокуса** при фокусе на вставленном `PasswordBox` внутри того же окна (самопроверка показала «событий фокуса: 0», фокус при этом на поле пароля, состояние «разрешено»). WPF поднимает события фокуса только при наличии UIA-подписчика — добавлена подписка UIA; WinEvent оставлен вторым источником.
- **Проба могла прочитать прежний элемент** сразу после события фокуса — добавлены подтверждающая проба для разрешающего ответа и перепроверки запрещающего.
- Ключ настройки примера `warnSeconds` отвергался шаблоном локальных ID (найдено самопроверкой плагина в 4D) — шаблон допускает camelCase.

## Не выполнено вручную (нужно проверить пользователю)

1. Реальные поля паролей в браузерах (Chrome/Edge/Firefox), менеджерах паролей, приложениях Win32/UWP, с повышенными правами — поведение провайдеров UIA разное. Реальные пароли не использовались.
2. Набор текста сразу после щелчка в поле пароля (скорость реакции; тесты проверяют порядок, а не физическую задержку вашей системы).
3. Подключение/отключение монитора, смена основного, разрешения и масштаба на лету; три и более монитора; монитор слева/сверху от основного на реальной системе.
4. Следование «под курсором» при быстром перемещении между мониторами с разным DPI.
5. Внешний вид кейкапов на 125/175/200 % масштаба.

## Ограничения и блокеры

- В Windows нет универсального признака поля пароля. Приложение, неверно сообщающее «не пароль», обнаружить нельзя; «нет данных» закрывает показ, но false от нестандартного провайдера принимается. Для таких приложений — список запрета и ручное скрытие.
- Таймауты соединения UIA самого клиента не настраиваются (не вызывается `IUIAutomation2`, чтобы не опираться на непроверенный индекс vtable); зависшая проба держит один рабочий поток до внутреннего таймаута UIA, показ при этом закрыт.
- Остаточная гонка: если событие фокуса доставлено позже ввода в новое поле внутри того же окна, этот ввод может пройти по старому решению. Синхронная проверка счётчика и окна фокуса перед каждой порцией сужает окно, но не исключает его.
- Кнопки мыши при закрытом показе видны (решение; можно изменить).
