## 1. Реализовано

### 1.1 Логотип

- `Backpack.Visual/Brand/LogoArt.cs` — единый параметрический источник: три пустые скруглённые рамки пирамидкой (одна сверху по центру, две снизу), равные промежутки, белая рамка со сдержанным объёмом (тёмная нижняя грань 6/256, мягкий блик на верхней кромке), чёрная середина и чёрный фон. Букв и символов нет.
- Из тех же чисел генерируется редактируемый SVG (`docs/brand/backpack-logo.svg`, упрощённый — `backpack-logo-small.svg`). Изменение `Spec` меняет и SVG, и иконки.
- `Assets/Backpack.ico` — 16, 20, 24, 32, 40, 48, 64, 128, 256 px (до 24 px — упрощённая версия); `Assets/BackpackTray.ico` — только упрощённая (толще рамки, без градиента и нижней грани) 16–48 px. Значок трея берётся из неё.
- Проверка малых размеров: `docs/brand/backpack-icon-sizes.png` — 16/20/24/32/48 px на светлой (#F3F3F3) и тёмной (#202020) панели, увеличено ×6 без сглаживания. На 16 px упрощённая версия читается как три рамки; полная на 16–20 px размывается (поэтому в ICO для них используется упрощённая).
- Логотип не зависит от стиля оверлея; он же в боковой панели главного окна и на странице «О программе».

### 1.2 Рендеры кейкапов

`KeycapControl` — общая основа (подпись, символ, метка «R/num/?», бейдж, ход нажатия); рендер задаёт только геометрию. `OverlayPresenter` при смене рендера **заменяет элемент**, сохраняя запись: `Id`, фазу, поколение, прозрачность; идущее исчезновение продолжается, оживление и защита от устаревшего завершения работают (тест `RendererSwap_KeepsIdentity_PhaseAndRejectsStaleCompletion`).

| Рендер | Источник | Особенности |
|---|---|---|
| lowprofile | Keyviz, формулы 2A ST-02/03 | без изменений поведения |
| laptop | ST-04 | высота 2.25·S, вертикальный градиент (OKLCH +0.1), блик сверху, внутренняя тень при нажатии, рамка снаружи; тень — смещённая подложка без размытия (не CSS blur) |
| pbt | ST-05 | корпус 2.75·S, градиент «вниз-вправо», верхняя часть 2.2·S, ход 0.15·S |
| minimal | ST-06 | только подпись/символ, масштаб 0.95, без бейджа |
| **объёмный** | собственный | вид спереди-сверху (по просьбе владельца, сначала был изометрический вариант 2:1 — заменён); выдавленный контур, верхняя грань светлее боковин, тёмный контур, подпись в плоскости грани (вертикальное сжатие не сильнее 0.85 ради читаемости), при нажатии грань опускается вместе с подписью; формы: квадрат, компактная 1.5 (служебные клавиши и пробел), Г-образный Enter (переключатель) |

Весь код рендеров — собственный WPF по формулам из спецификации 2A; код, таблицы и изображения Keyviz не копировались (лицензия GPL-3.0 при неопределённой лицензии Backpack — см. отчёт 3A). Цветовая математика OKLab — `Rendering/ColorMath.cs` (публичные формулы Ottosson).

Малые размеры: служебные подписи ужимаются не ниже 0.4·S, подпись не обрезается (без `TextTrimming`, без переноса); проверено тестом на S = 12 для «Backspace», «CapsLock», «Ctrl», «Esc», «PrintScreen» у четырёх рендеров и визуально на листе `docs/review/phase2e/sheet-keycaps-small.png` (S = 16, все пресеты, Ctrl, Alt, Win, Esc, стрелки, Enter, пробел, Bksp, «EN»).

### 1.3 Каталог стилей

Понятия разведены (и объяснены в справке `11-styles.md`): **рендер** (код), **пресет** (встроенный стиль `backpack.*`, неизменяемый), **пользовательский стиль** (файл `styles\u-….json`), **профиль** (полная копия оформления + поведение + положение).

- Встроенные пресеты: 11 кейкапов (по 2 на lowprofile/laptop/pbt/minimal, 3 объёмных — лавандовый, мятный, розовый), 4 индикатора («как кейкапы» + тёмная/светлая «пилюля», акцент, контур), 10 мышей (2 контурных, 2 сплошных, **4 ретро** — серо-голубой, бежевый, графитовый, приглушённый шалфей, 2 скетча). Палитры — собственные значения.
- Карточки каталогов в «Внешнем виде», «Мыши», «Раскладке»: плитки с миниатюрой настоящим рендером на светлом и тёмном фоне, название, «встроенный/мой · рендер», выбранное состояние (акцентная рамка), строка статуса («Выбрано», «На основе … • изменён», «Стиля этого профиля нет в каталоге…»).
- Операции: сохранить (для встроенного — создаёт копию), сохранить как новый, дублировать, переименовать и удалить (только свои), восстановить, импорт, экспорт, открыть папку.
- Отдельный выбор рендера: «Способ отрисовки» (меняет только геометрию, цвета сохраняются). Переключатель индикатора «Like keycaps / Own» переименован в «Источник оформления: Как у кейкапов / Собственный стиль»; каталог индикатора — отдельная карточка.
- Хранение: `styles\` рядом с настройками (в `%APPDATA%\Backpack` или portable `Data`), атомарная запись, повреждённые файлы пропускаются и не удаляются (счётчик показывается).
- Формат `backpack-style` 1 (`docs/settings/backpack-style.schema.json`): только данные в форме разделов темы; неизвестное поле, неверное значение, «xaml»/«assembly» и прочее отклоняют файл целиком; более новая версия — понятное сообщение; ≤ 64 КБ; id `backpack.*` зарезервированы.
- Конфликты id: тот же id и те же параметры — дубль не создаётся; тот же id и другие параметры или id встроенного — новый id и «(импорт)» в имени; существующий файл не перезаписывается.
- Профиль формата 2: настройки формата 3 (полная копия параметров) + необязательный `styles` (до 16) — пользовательские стили, на которые ссылается профиль. Импорт переносит их в каталог с тем же разрешением конфликтов и переписывает ссылки. Без каталога или без файла стиля оформление не теряется (тест `ProfileExport_EmbedsUserStyles_…`).
- Стиль кейкапа не содержит размер, подписи, анимацию; стиль мыши — размеры у курсора и боковые кнопки (это профиль/оборудование).

### 1.4 Мышь

- `Rendering/MouseIcon.cs` — собственная геометрия 40×56 без проводов; четыре семейства: **контурный** (овал, перегородка, колесо), **сплошной** (залитые части с промежутками, отдельное колесо), **ретро** (светлые кнопки, более тёмный низ и колесо), **скетч** (неровный контур с асимметрией, второй штрих, колесо с насечками). По изображениям Icons8 сделаны только собственные контуры; из скриншотов ничего не вырезалось.
- Нажатие меняет только свою часть (левая, правая, колесо, боковая); Unknown — пунктир части; размеры, цвета (контур, подложка, корпус, нажатие, стрелка), прозрачность через альфу.
- Боковые кнопки: скрыть / одна / две, слева / справа (по умолчанию две слева). Автоопределения нет: достоверного источника количества кнопок нет; в UI и справке сказано, что дополнительные кнопки часто переназначает драйвер.
- Значок в ряду использует тот же код (контурный, цвет текста кейкапа). Мышь в ряду и у курсора по-прежнему независимы; круг заметности — с отдельными настройками.

### 1.5 Прокрутка (обоснованное изменение захвата)

Раньше прокрутка сводилась к счётчику щелчков. Минимальное расширение:

- `InputKind.Wheel`, `WheelAxis`, поле `InputEvent.Delta` (знаковое, единицы WHEEL_DELTA; мелкие значения высокоточных колёс сохраняются);
- `CaptureState.ObserveWheel` — событие с номером последовательности в кольце, **без** изменения таблицы удержания; нулевое смещение не публикуется; потеря при переполнении увеличивает эпоху как обычно;
- источники: Raw Input `RI_MOUSE_WHEEL`/`RI_MOUSE_HWHEEL`, LL `WM_MOUSEWHEEL`/`WM_MOUSEHWHEEL`;
- `SourceModel` передаёт импульс получателю (`WheelObserved`) и не хранит его; снимок колесо не восстанавливает; сравнение источников колесо игнорирует;
- на значке у курсора — короткая стрелка (вверх/вниз/влево/вправо), длительность и цвет настраиваются; смена направления — сразу; средняя кнопка и прокрутка независимы. В ряду кейкапов прокрутка **не показывается** (сказано в UI, справке и release notes).

### 1.6 Сочетания

- Правило объединения `ChordRule`/`ChordMode`: «С Ctrl, Alt, Shift, Win» (прежнее) или «Любые одновременно удерживаемые клавиши». Одновременность — пересечение достоверных Down (не выдержка, не Unknown). Смена правила действует на следующие нажатия.
- Фильтр «только сочетания» при «любых одновременных» показывает группы из двух и более клавиш. Переключения не возвращают скрытые старые записи.
- Предупреждение о перекрытии нажатий при быстрой печати — в UI («Клавиши и сочетания», «Главная») и справке.
- Ограничение получения вынесено отдельно: «Backpack показывает только то, что клавиатура и Windows сообщают программам».

### 1.7 Главное окно, «Главная», «О программе»

- Класс `SettingsWindow` стал главным окном (имя сохранено ради совместимости тестов и кода 2D). Навигация: Главная; **Настройки** — раскрывающаяся группа (раскрывается сама при переходе в её раздел); Профили; Справка; О программе. Диагностика — «Справка и диагностика» внутри настроек; окно диагностики открывается по кнопке, при обычном запуске не показывается.
- Обычный запуск открывает «Главную» (`--minimized` — только трей); щелчок по значку трея открывает главное окно; × главного окна по умолчанию — в трей, по выбору — выход; «Выйти» — полный выход. Окно диагностики в обычном режиме закрывается как обычное окно.
- «Главная»: показ/скрытие отображения, активный профиль, быстрые переключатели, запуск линзы и рисования, переходы. Технические счётчики там не показываются.
- «О программе»: логотип, версия и канал (из `AssemblyInformationalVersion` и `AssemblyMetadata`), дата выпуска **из метаданных** (у сборки разработчика — «нет даты выпуска»), автор soobshoob и ссылка https://github.com/soobshoob (открывается после подтверждения), лицензия проекта — «ещё не выбрана», сторонние лицензии, проверка обновлений (см. 3A).
- Темы: новые элементы (`Ko.NavGroup`, `Ko.Tile`) в общем словаре, `DynamicResource`; самопроверка проходит все разделы в 3 языках × 2 темах.

### 1.8 Горячие клавиши

`Hotkeys/Hotkeys.cs`: `HotkeyManager` (RegisterHotKey на собственном message-only окне, `MOD_NOREPEAT`), `HotkeyRules` (нужны Ctrl/Alt/Win; список известных системных сочетаний, в т. ч. Win+Space, Alt+Tab, Win+L), состояния «активна / занята другой программой / конфликт / зарезервирована / недопустима / ошибка / приостановлена». По умолчанию Ctrl+Alt+Shift+O (показ/скрытие), +Z (линза), +D (рисование), +R (радиальное меню). Запись сочетания в окне приостанавливает регистрации и возвращает их при выходе из поля или закрытии окна. Применение — без перезапуска захвата. Хранение — `app.json` (этот компьютер), импорт профиля не меняет. F1 остаётся локальной.

Показ/скрытие отображения: по умолчанию кейкапы, индикатор и мышь (части настраиваются); захват продолжается; при возврате отпущенные записи убираются (`DisplayModel.DropReleased`), удерживаемые видны; скрытие закрывает линзу и рисование.

## 2. Установленные причины ошибок

### 2.1 Win-сочетания (Win+Space и др.)

Цепочка проверена по коду и тестами на искусственных событиях:

| Звено | Результат |
|---|---|
| получение события → состояние | Win (E0 5B/5C) и Space нормализуются верно в обоих источниках; автоповтор помечается, дубль не создаётся |
| состояние → группа | Win — модификатор; Space при удержании Win присоединяется; все порядки отпускания и повтор Space дают одну группу «Win Space» с счётчиком |
| группа → фильтр | «Только сочетания» показывает группу; одиночная Win скрыта намеренно |
| фильтр → рендер | обычный ряд |
| смена переднего плана | `EVENT_SYSTEM_FOREGROUND` только проверяет окно оверлея; модель не меняется |
| сбросы | смена рабочего стола, блокировка, сон → Win в Unknown → следующая клавиша не образует сочетание (так и задумано: Unknown — не удержание) |

**Ошибки отображения в цепочке на этих последовательностях не найдено** (тесты `WinSpace_AllReleaseOrders_FormOneGroup`, `WinSpace_RepeatedSpaceWhileWinHeld_…`, `ContextReset_WhileWinHeld_…`). Синтетический показ «предполагаемого» сочетания не добавлялся; Win+Space не блокируется (Backpack не подавляет ввод).

Установлено ограничение отображения: Windows показывает «Пуск», поиск, представление задач и другие панели оболочки в слоях выше обычных topmost-окон; без uiAccess (запрещён заданием) оверлей их не перекрывает. Это закрывает оверлей при части Win-сочетаний — описано в справке «Что делать, если…».

Чтобы отделить «событие не получено» от «получено, но не показано», добавлены **агрегированные счётчики** на источник: `ModifierChords`, `WinChords` (новая не-модификаторная клавиша стала Down при достоверно нажатом модификаторе / Win), `WheelEvents`. В `compare` расхождение Raw Input и LL-хука показывает потерю получения у одного источника. Клавиши и порядок не записываются (тест экспорта обновлён только списком разрешённых имён числовых полей).

### 2.2 Ложная проверка «Stylе not implemented»

При чтении настроек любой стиль кроме lowprofile давал сообщение «стиль недоступен» — теперь все рендеры поддерживаются, сообщение и ключ удалены.

### 2.3 Содержимое у нижней границы превью

Проверено по разметке и тестом: область прокрутки — отдельный элемент `DockPanel` ниже карточки превью; **они не пересекаются** ни при высоте 480, ни при 820 (тест `MainWindow_…ScrollAreaNeverOverlapsPreview…`). На снимках владельца видно частично прокрученное содержимое у верхней кромки области прокрутки: без визуальной границы оно выглядит как уходящее «под превью». Это вывод по разметке, а не установленная по снимку причина. Изменения: линия края области прокрутки появляется при прокрутке, область обрезается своими границами, высота превью 110–190 по высоте окна (на низком окне больше места параметрам).

### 2.4 Найдено и исправлено в ходе работы

- Высота laptop превышала расчётную на толщину рамки (тест) — рамка внутри высоты.
- `StyleSerializer.Read(JsonObject)` не читал целые числа у объекта, собранного в памяти (`JsonValue<int>`) — нормализация через текст (тест).
- Изометрическая подпись Enter втискивалась перед вырезом — перенесена в часть клавиши на всю глубину; затем рендер заменён на вид спереди по просьбе владельца.

## 3. Гипотезы (не подтверждены)

1. **Получение Win-сочетаний источником Raw Input.** Если другая программа или оболочка обрабатывает сочетание LL-хуком и не передаёт дальше, Raw Input его не увидит, а LL-хук Backpack (установленный позже, вызывается раньше) — увидит. Проверяется сценарием §5 в `--lab --source=compare` по счётчикам `WinChords`.
2. **Эвристика устаревшего Down.** Если клавиатура или драйвер не повторяют удерживаемую Win, после ~1.25 с без повторов Win становится Unknown, и Win+Space не образует группу (тест фиксирует поведение). Счётчик `StaleNoRepeat` в экспорте покажет, случается ли это.
3. Панели оболочки (поиск, «Пуск») перекрывают оверлей при части Win-сочетаний — вероятно, основная видимая причина жалобы; подтверждается ручным сценарием.

## 5. Подготовленные, но не выполненные ручные проверки

**Win-сочетания (10 минут).** `Backpack.exe --lab --source=compare --settings=%TEMP%\ko\settings.json`, «Клавиши и сочетания» → «Все клавиши».
1. Win+Space (удерживая Win, нажать Space 2–3 раза). Ожидается «Win Space» с бейджем. Раскладка переключается (Backpack не мешает).
