### 1.3 Решения, принятые по ходу

- **Размещение окна и выравнивание содержимого разведены** (Phase 2A §3.3а). В 2A для этапа 1 было указано «8 позиций», а в схеме `alignment9` — 9 значений. Теперь окно оверлея имеет 9 якорей, включая центр (дополнение Backpack; в UI Keyviz центр заблокирован), и хранится в настройках компьютера. Выравнивание подписи внутри кейкапа — параметр темы `text.alignment`, этап 2.
- **Окно оверлея — полоса**: ширина рабочей области минус отступы, высота по группе (+ поле под бейдж). Окно не меняет размер при каждом нажатии. Полноэкранное окно не используется (Phase 0 R9).
- **Анимации — собственный расчёт по внедряемым часам**, тик от `CompositionTarget.Rendering` только пока анимации идут. Так тесты детерминированы, а завершение исчезновения проверяемо защищено поколением. Индикатор раскладки использует обычную `DoubleAnimation` WPF с той же защитой `Completed` поколением.
- **Один формат цветов и единиц.** `ThemeColor` хранит `#RRGGBB`/`#RRGGBBAA` (альфа последней, как в теме) и единственный переводит в WPF `#AARRGGBB`. Раздел `appearance` файла настроек имеет форму разделов темы; тест оборачивает его в тему и проверяет по схеме.
- **Подписи.** Иконок на этапе нет. Чтобы чек-лист 1B по-прежнему различал левые/правые клавиши и Num Enter, вместо иконки сверху показывается пометка «L»/«R»/«Num»/«Mouse», а снизу — короткая подпись (раскладка Keyviz «иконка + короткий текст»).
- **Unknown** — непрозрачная грань, приглушённая подпись и «?». Первый вариант с полупрозрачной гранью отвергнут после просмотра снимка: через грань просвечивала «юбка».
- **«Без анимации»** мгновенно завершает появление и исчезновение. Нажатие остаётся анимированным 100 мс, как в Keyviz, где `animation: none` влияет только на варианты входа и выхода.
- **Выдержка** по умолчанию теперь из настроек (5000 мс, как в Keyviz); прежнее значение стенда 2000 мс — только через `--linger-ms`.
- **Индикатор: опрос раз в 100 мс без WinEvent.** Смена окна видна по смене HWND в опросе. Задержка показа — 2 опроса (≈ 100–300 мс). Отдельный `EVENT_SYSTEM_FOREGROUND` не добавлялся, чтобы не связывать Visual с хуками стенда.
- **Справка — собственный разбор подмножества Markdown** в `FlowDocument`; без WebView2, без NuGet, без загрузки XAML. Тест требует, чтобы все разделы укладывались в подмножество.

## 3. Оставшиеся ручные проверки (владелец)

### 3.1 Команда запуска

```powershell
dotnet run --project lab/src/Backpack.App -- --source=raw
```

Для проверки без затрагивания своих настроек добавьте `--settings=%TEMP%\backpack-check\settings.json`.

### 3.2 Короткий сценарий: визуал → настройки → раскладка → F1 → перезапуск

1. **Визуал.** Откройте Блокнот, печатайте. Нажмите Ctrl+Shift+K: три кейкапа lowprofile; у нажатых грань опущена. Отпустите — через ~5 с каждый плавно исчезает (своё время у каждой клавиши). Нажмите A, отпустите, дождитесь начала исчезновения и сразу нажмите A снова — кейкап возвращается, второго не появляется. Курсор всё время остаётся в Блокноте; клик по кейкапу проходит в Блокнот.
2. **Настройки.** «Настройки…» в окне диагностики. Двигайте «Размер S», меняйте «Основной цвет» (например `#2E3138`) и «Цвет текста» (`#F2E6D0`): превью и оверлей меняются сразу. «Без анимации» — кейкапы появляются и исчезают мгновенно. «Размещение» → центр (•): оверлей переезжает в центр экрана. «Показать пример на оверлее» — 6,5 с примера.
3. **Раскладка.** Переключите язык в Блокноте сочетанием и отдельно — мышью на панели задач: каждый раз один раз появляется код («RU»/«EN»). Переключение языка, пока активно окно настроек, индикатор не показывает. Выключите индикатор — переключения больше не показываются.
4. **F1.** В окне настроек на вкладке «Цвета» нажмите F1 — справка открывается на разделе «Цвета». Перейдите на вкладку «Раскладка» и снова F1 — то же окно переходит к разделу индикатора, второе окно не появляется. В справке: поиск «IME», ссылки, «Назад».
5. **Перезапуск.** Закройте окно диагностики, запустите стенд снова: размер, цвета, положение и состояние индикатора сохранились.

Записывайте наблюдения в журнал (без набранного текста).

## 4. Ограничения и что осталось

- **Кастомизация не завершена**: один стиль; нет файлов тем, импорта и экспорта, импорта Keyviz, истории, фильтров, иконок, символов, выделения модификаторов, регистра и выравнивания подписи, выбора шрифта, эффектов мыши, анимаций zoom/float/slide и перестройки ряда, выбора монитора. Этапы — Phase 2A §6.7, построчно — §2.15.
- **Бейдж счётчика** — предварительный (всегда включён, без анимации появления).
- **Подписи** — собственная US-таблица; пометки L/R/Num вместо иконок; буквы по текущей раскладке не меняются (не утверждено).
- **Индикатор раскладки**: язык берётся из HKL потока, которому принадлежит окно переднего плана. Для консоли, Терминала, UWP и elevated-окон не проверено. Режим IME не виден. Уведомления TSF доступны только своему потоку. Названия раскладок через раздел реестра `Keyboard Layouts` — не документированный контракт, при неудаче — номер. Transient LANGID (0x2000…) — «?» или название.
- **Окно настроек**: цвета вводятся текстом `#RRGGBB[AA]` (палитры нет); выдержка в окне — до 20 с (файл допускает до 60 с); превью уменьшается, если пример не помещается.
- **Размещение**: только основной монитор; при смене конфигурации дисплеев полоса пересчитывается, но отключение и подключение мониторов и смена DPI на лету не проверялись.
- **Справка**: подмножество Markdown (без картинок, цитат, HTML, заголовков глубже ###); подсветка поиска — по первым вхождениям в каждом фрагменте текста.
- **Визуальная точность** против Keyviz не измерялась: шрифт (статический Inter против вариативного), сглаживание рамок, кривые анимации остаются «ИЗМ».
