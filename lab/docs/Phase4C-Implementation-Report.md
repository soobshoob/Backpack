# Phase 4C — «Фокус», увеличение у курсора, рисование

## Реализовано

| Область | Что сделано |
|---|---|
| Общий движок | `Presentation/MagnifierSurface.cs`: Magnification API, раздельные **источник** (прямоугольник рабочего стола) и **окно вывода** (физические пиксели), увеличение = вывод / источник; форма — скруглённый прямоугольник или эллипс (`SetWindowRgn`); рамка/тень/свечение/отметка реальной точки — отдельное click-through окно; собственные окна Backpack исключены из источника (нет рекурсии); системный курсор в изображение не попадает (нет «второго курсора»); обновление ~60 Гц только пока открыт; недоступный источник скрывает изображение. Счётчик открытых экземпляров для проверки освобождения. |
| «Фокус» | `Presentation/Focus.cs`: `FocusRegion` (чистая модель: из выделения, перемещение вывода, перемещение источника, изменение размера вывода с сохранением увеличения, смена увеличения, ограничение монитором), `FocusController` (выделение → просмотр → явное редактирование → Esc), `DimWindow` (чёрный слой с прозрачностью, скруглённое «окно», рамка, свечение, мягкость края через BlurEffect, появление по времени), `FocusEditWindow` (перетаскивание — вывод, Ctrl+перетаскивание — источник, правый/нижний край — размер, Esc/Enter/двойной щелчок — выход). Режим просмотра пропускает клики. Затемнение — только мониторы по политике (по умолчанию монитор области). Прежнее сочетание «Живая линза» запускает «Фокус: Линза». |
| Пресеты | Нейтральный — 70 %, 16, 2, `#D4D4D4`, 0, 150 мс; Изумрудный — рамка `#31C99A` со свечением; «Свой». Все размеры — DIP (единицы концепта «px» не трактуются как физические пиксели). Тема приложения рамку не меняет. |
| Увеличение у курсора | `Mouse/CursorZoom.cs`: режимы «При удержании» (опрос состояния клавиш назначенного сочетания каждый кадр — RegisterHotKey не сообщает об отпускании; аварийный предел 5 мин), «Всегда», «На месте» (живое изображение). Следование — экспоненциальное сглаживание по времени кадра (без sleep), постоянная времени по умолчанию 50 мс; источник центрирован в **реальной** точке указателя, центр вывода отмечен крестиком; вывод удерживается внутри монитора под указателем, размер — по его DPI. Значок мыши: «держать рядом» (временный сдвиг) или «скрывать»; после завершения восстанавливается, сохранённые настройки не меняются (`MouseCursorController.SetZoomInteraction`). Esc (в режимах удержания/на месте), блокировка, скрытие отображения, выключение — аварийное закрытие. |
| Умный карандаш | `Presentation/ShapeRecognizer.cs`: только прямая, эллипс/окружность, прямоугольник; пороги в долях размера штриха (масштабонезависимо), минимальная длина 28 DIP, замкнутость, вытянутые петли отвергаются; низкая уверенность → штрих остаётся. Локально, штрихи никуда не передаются. Результат — редактируемая WPF-фигура с цветом, толщиной, прозрачностью и типом линии штриха. Замена — отдельный шаг истории: отмена возвращает исходный штрих. Стрелка не распознаётся (отдельный инструмент). |
| Нумерованные отметки | Инструмент «①»: следующий номер = максимум видимых номеров текущей серии + 1 (иначе начальный) — после отмены нумерация согласована; начальный номер и сброс (команда «Сбросить нумерацию»); цвет — текущий цвет рисования, размер — настройка; перемещение перетаскиванием — шаг истории. |
| История | Undo/redo обобщены: присутствие каждой фигуры пакета переключается — замена и перемещение выполняются и отменяются одним шагом; прежние сценарии (фигура, очистка, исчезновение по сроку) работают как раньше. |

## Результаты проверок

- Visual `Phase4CTests` (11): распознавание прямой, окружности, эллипса, прямоугольника с дрожанием; каракули, «S», короткий штрих, открытая дуга — без замены; масштабонезависимость (×0.6/×1/×2.5); замена штриха с сохранением толщины, пунктира и прозрачности, отмена → штрих, повтор → фигура, зигзаг остаётся линией; нумерация после отмены, повтора, перемещения и сброса; независимость источника и вывода «Фокуса», ограничение монитором с отрицательными координатами; попадание в рамку/край; сглаживание, удержание в мониторе, центр источника в реальной точке; режимы увеличения без Magnification API; реестр команд и сочетания по областям.
- Самопроверка настоящих окон (шаг 10): «Фокус: Линза» — окно выделения захватывает мышь, после выделения Magnification «Live» (17 кадров, 1.5×) и мышь не захватывается; редактирование захватывает мышь, Esc возвращает в просмотр без изменения области, повторный Esc выключает и освобождает Magnification; «Затемнение» — одно окно только на мониторе области, click-through; выключенный инструмент не запускается; увеличение «Всегда» — Live, значок скрыт, выключение возвращает значок; «На месте» — создание и снятие; «При удержании» — видно при удержании, отпускание скрывает; Magnification освобождён.
- Прежняя самопроверка рисования (7 вариантов панели, F2 только в режиме, настоящий снимок без панели, радиальное меню, текст) — без изменений, проходит.

## Не выполнено вручную

1. Реальное выделение области мышью, перетаскивание и изменение размера в режиме редактирования, поведение кликов сквозь линзу и затемнение в разных приложениях.
2. Увеличение у курсора на втором мониторе с другим DPI, у краёв и при переходе между мониторами; ощущение плавности при разных значениях сглаживания; удержание сочетания с потерей фокуса.
3. Умный карандаш живой мышью (пороги подобраны на синтетических штрихах) и перетаскивание отметок.
4. Защищённое от захвата содержимое (DRM) в линзе и увеличении — будет чёрным, как в других программах.

## Ограничения

- Изменение размера — за правый и нижний край (и угол); левый/верхний края не тянутся.
- Размытие в «Затемнении» не реализовано (не требовалось); мягкость края — размытие самого слоя.
- Отмеренная задержка изображения не измерялась; 40–60 мс концепта — только параметр сглаживания.
- Для команды «Увеличение: удержание» поддерживаются сочетания с обычными клавишами; опрос `GetAsyncKeyState` читает только состояние клавиш назначенного сочетания.
