# Phase 4H — отчёт о реализации (Backpack 0.4.0-preview.5)

Исходная версия — 0.4.0-preview.4. Работа шла в двух сессиях (передача — `Phase4H-Handoff.md`). Ничего не закоммичено и
не опубликовано; сайт и лицензия не менялись; сертификат не покупался. Процессы пользовательского Backpack (preview.4)
не закрывались; синтетический ввод отправлялся только при активном тестовом окне.

Пакет: `artifacts/release/Backpack-0.4.0-preview.5-win-x64.zip` (88,8 МБ, неподписанный),
SHA-256 `28f076c825b040971b1ea459e6a90ded29367cfa31cd20b60d6a2ccbe38c4ad3` (`SHA256SUMS.txt`, строки прошлых выпусков
сохранены). Заметки: `docs/release/RELEASE-NOTES-0.4.0-preview.5.md`.

Проверки после последних изменений: `KeyOverlay.Visual.Tests` 468/468, `KeyOverlay.Lab.Core.Tests` 106/106;
`selftest-ui` (Debug, с поставкой) — ok, 416 шагов; `verify-package -SelfTestUi` по zip — **46 PASS, 0 FAIL**.
Снимки — `lab/docs/Phase4H-images/`.

## 1. Значок на панели задач

- **Причина.** Окну давался векторный `DrawingImage`, размер которого — границы линий (~24×30 DIP); WPF клал его 1:1 в
  значок 48×48, и на панели (150 %) рюкзак занимал 24×30 из 48 px. Прежние правки ICO (95 % заполнения) до панели не
  доходили: панель брала значок окна, а не ресурс EXE.
- **Исправление.** `LogoArt.WindowIcon` — многоразмерный ICO 16…256 с толщиной линий для малых размеров; Assets/*.ico
  перегенерированы. `WM_GETICON`: big 48×48, small2 24×24, рисунок 34×46 из 48.
- **Проверки.** Распакованный пакет preview.5, запуск напрямую и через тестовый ярлык (в scratchpad, без закрепления):
  `01-taskbar-package-direct.png`, `01-taskbar-package-shortcut.png` — рядом в той же панели работающий у пользователя
  preview.4 (маленький тонкий рюкзак) и preview.5 (той же высоты, что VS Code и ChatGPT).
- **Ограничения.** Кэш значков и закрепления не сбрасывались. Если у пользователя закреплён старый ярлык, его значок
  берётся из кэша закрепления: открепить и закрепить заново (или обновить ярлык) — других действий не нужно.

## 2. Заголовок окна

- **Причина.** Отдельная полоса заголовка с маленьким названием дублировала логотип над меню.
- **Исправление.** `WindowShell.IntegratedTitle`: полосы нет, кнопки окна — слой справа сверху в верхней строке
  интерфейса, шапка страницы оставляет им место; знак «Backpack.» крупнее (40/30) с отступом 18. Имя окна «Backpack» для
  Alt+Tab и доступности сохранено.
- **Проверки.** WM_NCHITTEST (caption, кнопка максимизации → Snap, клиентские кнопки, края), перетаскивание, двойной
  щелчок, развёрнутое и узкое окно (`02-title-*.png`, `10-style-toolbar-before-after.png` — до/после на настоящих сборках).
- **Ограничения.** Диалоги и окно справки сохраняют компактную полосу.

## 3. Две подписи на кейкапах

- **Причина.** Дополнительная подпись привязывалась к углу области основной подписи, а не к грани кейкапа; поэтому «л»
  прилипала к K и требовала крайних смещений.
- **Исправление.** `TwoLabelLayout` (settings v9): размер основной (0,78) и дополнительной (0,42) — доли лица кейкапа;
  угол; сдвиги −15…+35 % от безопасной точки у угла (положительный — к центру). Размещение в `KeycapControl.PlaceSecondary`
  по реальной грани всех рендеров. Миграция v8: угол сохраняется, размер ×0,86, сдвиги обнуляются. Схемы обновлены.
- **Проверки.** 240 случаев (рендер × размер × угол) без пересечений и выхода за грань; листы `03-two-labels-*.png`
  (тёмный, светлый, Spectral). Раскладки ru/uk/el/de: греческая W → ς/Σ, украинский апостроф в стандартной раскладке —
  Ё (так устроена раскладка Windows); найдена и исправлена потеря подписи у вариантов раскладок (uk Enhanced, HKL
  с расширением знака).

## 4. Фирменная точка

- **Исправление.** `Brand/Wordmark.cs` — «Backpack» + изумрудная точка на базовой линии (Ko.LogoBrush, мягкое свечение в
  Neon/самоцветах) в меню, на «Главной» и «О программе». В именах EXE, путях, ID и обычном тексте точки нет.

## 5. Рисование и индикатор раскладки — плагины

- **Исправление.** SDK 1.2: `overlay.draw` (хост рисует холст: все прежние возможности — панель и режимы, радиальное
  меню, фигуры, умный карандаш, текст, номера, цвета, отмена/повтор, снимки), `overlay.indicator`, `input.layout`
  (код, название, причина; нажатий нет), `UpdateSettings`, `OnToolState`, команды `whileTool` (F2 только пока открыт
  холст), сочетание и значок команды по умолчанию, скрытые настройки, сцены превью `drawing`/`indicator`. Плагины
  `lab/samples/Drawing` и `lab/samples/LayoutIndicator`. Определение раскладки, ребазлайн при старте/сне, приватность,
  подписи клавиш, профили и управление плагинами остались в ядре. Встроенные страница «Рисование», команды рисования,
  переключатель индикатора (меню, трей, «Главная») удалены; страница «Раскладка» стала «Стиль индикатора» (каталог стилей
  индикатора — система стилей). Плагины-обёртки по ID нет: хост не знает ID этих плагинов.
- **Поставка «От создателя».** `Plugins\bundled.json` (файл, ID, версия, SHA-256; `tools/write-bundled-index.ps1`).
  При запуске проверенные пакеты ставятся в каталог выключенными, код не запускается. Отметка — по совпадению с индексом,
  не по имени автора; это не подпись издателя. Пользовательский пакет с тем же ID отметки не получает. Удалённый
  поставляемый плагин не возвращается сам («Добавить снова»). Обновление из поставки сохраняет включение, пакет
  пользователя — выключен до включения.
- **Перенос при обновлении.** Настройки (`draw`, `drawing`, `markers`, `layoutIndicator`), сочетания (снятое остаётся
  снятым), пункты меню; уведомление; плагины выключены. Чистая установка ничего не переносит.
- **Проверки.** Тесты `Phase4HPluginsTests` (индекс, подмена хеша, установка без запуска, отметка, удаление, обновление,
  перенос, граница протокола, whileTool). selftest-ui на настоящих процессах: каталог → доверие → включение → команды →
  F2 только в режиме → Esc → плагин знает о закрытии → отключение во время работы (окна, команды, процесс) → удаление →
  повторное добавление; индикатор: наблюдение только при включённом плагине, пример, скрытие. Живые запуски: чистая
  установка из пакета (`05-plugins-clean-install.png`), обновление с данными preview.4 (`05-plugins-upgrade.png`,
  значения проверены в файлах). Страница плагина с живым превью панели — `05-drawing-plugin-page-uk.png`.
- **Ограничения.** ID плагинов сохранены как `com.example.*` (чтобы не терять установки 4G). Одновременно один холст.

## 6. Backpack Neon

- **Исправление.** Независимые настройки: основа, палитра, стиль поверхностей (Standard, Liquid Glass, Neon), материал и
  прозрачность (`AppearanceMaterial.Surface`; прежний материал LiquidGlass → Acrylic + стиль). Neon: самая тёмная основа,
  рамки цвета свечения с иерархией (разделители < карточки < поля < выбранное/фокус), свечение акцентов при любой палитре,
  светлый вариант со своими цветами, рамка окна DWM цвета свечения (Windows 11). Текст не светится. Высокая контрастность →
  стандартный стиль. Токены общие — применяется ко всем окнам, диалогам, меню, справке и страницам плагинов.
- **Проверки.** Тест: иерархия рамок, контраст текста ≥7, Neon темнее всех палитр — для 4 палитр × 2 основы. Снимки
  `06-neon-dark.png`, `06-neon-light.png`; живой экземпляр Neon + Acrylic 60 % — `06-neon-dark-acrylic-live.png`.
- **Ограничения.** Всплывающие меню без системного материала (плотная заливка).

## 7. Материалы подложек

- **Причина ограничения (измерено).** Эксперимент на layered click-through окне, как у оверлея (`07-overlay-*.png`):
  DWMWA_SYSTEMBACKDROP_TYPE (Mica/Acrylic) закрашивает весь прямоугольник окна непрозрачно; SWCA blur — чёрным; SWCA
  Acrylic реально размывает, но весь прямоугольник окна (SetWindowRgn не обрезает); окно размером с группу — квадратные
  углы или системные ~8 px с тенью, без плавного исчезновения. Ни один вариант не выполняет требований.
- **Исправление.** `BackdropMaterial`: Заливка и Прозрачная (без заливки, контур 1,25 DIP внутри прежних размеров) для
  группы кейкапов и значка мыши; Acrylic/Mica читаются, действует заливка, страница объясняет. Сохраняется в стилях и
  профиле, схемы обновлены. Превью на светлом и тёмном фоне (`07-backing-transparent.png`). Окна оверлея не менялись:
  пропуск щелчков, фокус, мониторы и DPI прежние.
- **Проверки.** `Phase4HBackdropTests`: сохранение, замена недоступного, одинаковая геометрия, отсутствие заливки.

## 8. Незакрытые проверки 4G

- **Наведение.** `SelfTest4H.cs`: настоящий указатель (SetCursorPos, без щелчков) только пока впереди окно самопроверки —
  линза, фокус, панель таймера: скрытое управление прозрачно для щелчков (WindowFromPoint), появление над оверлеем,
  переход на панель, удержание при перетаскивании, скрытие после ухода. 12 перемещений, пропусков 0; в пакете — PASS.
  Найдено и исправлено: тестовый путь перетаскивания не ставил удержание, как настоящий.
- **Приватность (4 провала 4G).** Причина установлена экспериментом (`scratchpad privexp`): если другой процесс держит
  передний план, WPF сообщает PasswordBox в фокусе и даже `IsActive=True`, а Windows/UIA — обычное поле другого процесса,
  куда и уходят нажатия. Продукт оценивает верно; провал — синхронизация теста (не проверялся системный передний план, а
  диагностика брала `IsActive` WPF). Тест теперь проверяет `GetForegroundWindow` перед каждым шагом и пишет pid; при чужом
  переднем плане шаг помечается как условие окружения, а не засчитывается. Проверка не ослаблена.
- **Символы раскладок** — см. п. 3.
- **Fn.** Не имитировалась. Режим `--fn-trace` (45 с или до Esc, только служебные клавиши, при закрытой приватности —
  ничего) и сценарий `lab/docs/Phase4H-Fn-check.md` (около минуты, одно физическое нажатие). **Требуется ваш прогон.**
