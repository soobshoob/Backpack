## 2. Что реализовано по каждому замечанию

### 2.1 Кейкапы и символы

- **Явная таблица обозначений** (`Rendering/KeyLabels.cs`) для наборов **Windows / macOS / Linux** и видов **смешанный / символы / текст**:
  - набор меняет только подписи и символы, физическая клавиша и ввод те же;
  - запасной вариант: нет символа → короткая подпись; нет записи в таблице → название как есть;
  - неоднозначные macOS-подписи («Del» под ⌫ и под ⌦) в текстовом виде различаются полностью: «Delete» / «Fwd Del».
- **Компактные служебные клавиши:**
  - Space — символ ␣;
  - Delete — «Del» (на macOS — с символом ⌦);
  - Backspace — ⌫ «Bksp»;
  - Enter — ↵ (на macOS — ↩ «Return»);
  - Tab — ⇥;
  - Esc — «Esc» (на macOS — с символом ⎋);
  - стрелки — символы;
  - модификаторы — символ над подписью, как в Keyviz.

  Длинная служебная подпись ужимается до 0.4·S, чтобы клавиша не была шире модификатора (80 DIP при S = 32). Тест проверяет это для 11 клавиш во всех наборах.
- **Левая/правая и Num Enter** различаются маленькой угловой меткой «R» / «num» вместо подписей «LCtrl» / «Num Enter». Левые клавиши метки не имеют. Метки отключаются.
- **Символы** — собственная векторная геометрия (`Rendering/KeyGlyphs.cs`, сетка 24×24, линия 2, масштабируется вместе с толщиной). Не из Keyviz, не из Lucide, не символы шрифтов. Значок Win — нейтральная сетка 2×2, а не логотип.
- **Счётчик повторов** включается и выключается.
- Семантические имена клавиш дал Core (`KeyInfo.Semantic`). Визуальный слой по-прежнему не зависит от Core.
- **Не сделано:** стили laptop/pbt/minimal, символы второго ряда, выделение модификаторов цветом, менеджер тем. Соответствие Keyviz и пиксельная идентичность не заявляются.

### 2.2 Позиционирование

- **Причина установлена (по коду).** В 2B `OverlayPlacement.Compute` сужала полосу окна симметрично на `MarginX` с обеих сторон. При центральном якоре это не сдвигало группу.
- **Разделены два понятия** (`Windows/OverlayPlacement.cs`):
  - **расстояние от края** (`EdgeX`, `EdgeY`) действует только по оси, где якорь у края;
  - **смещение от якоря** (`OffsetX` вправо, `OffsetY` вниз) действует для всех девяти якорей, включая центр.
- **Окно** — полоса во всю ширину рабочей области; группу по горизонтали размещает `AnchorPanel`. Группа не выходит за рабочую область: проверено для 9 якорей, S = 8/32/128, смещений ±5000 и отрицательных координат монитора.
- **В настройках:**
  - выбор якоря 3×3;
  - подписанные направления «Смещение вправо (→) / вниз (↓)»;
  - неактивное расстояние от края по центральной оси с объяснением;
  - схема-превью положения и «Вернуть положение по умолчанию».
- **Миграция** формата 1 → 2: `marginX/marginY` → `edgeX/edgeY`, смещения 0. Тест подтверждает то же место на экране, что давала формула 2B.

### 2.3 Раскладка

- **Причина «работает только в ChatGPT» не установлена:** реальное переключение языка не воспроизводилось (см. §3.3).
- **Исследование цепочки** окно → поток → HKL → детектор → показ, пассивно, без смены языка (§3.3). Факты:
  - у трёх раскладок пользователя все потоки сообщают один HKL;
  - у Electron-приложения на переднем плане поток фокуса совпадает с потоком окна;
  - у неактивных окон `GetGUIThreadInfo` не отдаёт окно фокуса, поэтому без ручного переключения сравнить потоки у Блокнота, Терминала и Проводника нельзя.
- **Исправление по документации Microsoft** (`Layout/LayoutProbe.cs`):
  - `GetGUIThreadInfo(0)` возвращает данные потока переднего плана («If this parameter is NULL, the function returns information for the foreground thread»), включая `hwndFocus` — окно с фокусом клавиатуры, которое может принадлежать другому потоку;
  - HKL берётся из `GetKeyboardLayout` для потока окна с фокусом («input locale identifier for the thread»);
  - запасной путь — `hwndActive`, затем поток-владелец окна переднего плана (способ 2B).

  Обоснование: раскладку меняет поток, обрабатывающий ввод с клавиатуры, а не обязательно поток, создавший верхнее окно. Помогает ли это в конкретных программах пользователя — гипотеза до ручной проверки.
- **Диагностика без чувствительных данных:**
  - итог последнего опроса и последнее решение: нет окна / раскладка недоступна / окно KeyOverlay / ждём подтверждения / исходное значение / без изменений / показано в окне / показано при переходе / не показано — выключено настройкой;
  - откуда взят HKL;
  - сколько раз поток фокуса отличался от потока окна и сколько раз HKL у них различался.

  Строки видны в окне диагностики, в экспорте — раздел `Visual.Layout`. Окон, заголовков, процессов, кодов раскладок и клавиш нет: тест экспорта проверяет набор полей.
- **Различение случаев:** смена в окне и переход между окнами (`ShownInWindow` / `ShownWindowSwitch`), собственные окна (`OwnWindow`), неизвестный результат (`NoForeground` / `Unavailable`). Способ переключения (клавиатура или панель задач) не различается намеренно: определение идёт по фактическому HKL, а не по клавишам.
- **Оформление индикатора** (`Layout/LayoutIndicator.cs`):
  - наследование от кейкапов или своё: размер текста, цвета текста и фона с прозрачностью, рамка, скругление;
  - анимация: как у кейкапов / плавно / без;
  - позиция над кейкапами или по якорю на экране, со смещениями;
  - живое превью;
  - константа `codeSize = 40` удалена: при наследовании размер 1.125·S.
- **Изменения применяются к уже показанному индикатору сразу.** Срок показа отсчитывается от момента показа и не продлевается (тест с подменёнными часами).
- **Не делается:** определение по Alt+Shift/Win+Space, перехват текста, вмешательство в IME, повышение прав.

### 2.4 Фильтры отображения

- **«Все клавиши» / «Только сочетания»** (`Rendering/RowFilter.cs`) — только на уровне представления. Модели ввода и отображения не меняются, отпускания принимаются как прежде.
- **Семантика «только сочетания»:**
  - модификатор (Ctrl/Shift/Alt/Win) плюс хотя бы одна другая клавиша;
  - одиночный модификатор и обычная печать скрыты;
  - удерживаемый модификатор учитывается для следующего сочетания;
  - Shift + буква — сочетание;
  - Ctrl + кнопка мыши — сочетание, если мышь показывается в ряду.
- **Смена режима** не возвращает старые отпущенные нажатия: они подавляются до своего исчезновения. Удерживаемые показываются сразу. Зажатых элементов не остаётся (тест с презентером).
- **Мышь в ряду** включается отдельно; обозначение — значком с подсвеченной кнопкой или текстом.

### 2.5 Мышь у курсора

- **Независимый режим** (`Mouse/MouseCursor.cs`), выключен по умолчанию:
  - круг под указателем и значок мыши со смещением включаются отдельно;
  - нажатая кнопка подсвечивается (по умолчанию #22C55E), отпускание снимает подсветку;
  - Unknown — пунктир, не нажатие;
  - левая, правая и средняя кнопки — на корпусе значка; X1 / X2 — выступы слева.
- **Настройки:** размер значка, смещение, контур, фон, цвет нажатия, диаметр, цвет и непрозрачность круга.
- **Состояние кнопок** берётся из уже имеющейся модели основного источника (`SourceModel.AggregateOf`, только чтение).
- **Окно** no-activate и click-through, без панели задач.
- **Положение** — `GetCursorPos` по таймеру ~60 Гц, только пока режим включён, без глобального хука движения. DPI берётся у монитора под указателем, отрицательные координаты поддерживаются. После выключения и завершения таймер останавливается, окно закрывается (тесты и самопроверка). Координаты и история не сохраняются.

### 2.6 Спокойное отображение при быстрой печати

- **Причина установлена (по коду).** В 2B вытесненные кейкапы оставались в горизонтальном `StackPanel` в фазе исчезновения и занимали место рядом с новыми.
- **Режим «Без следа»** (`TrailMode.None`, рекомендуемый, по умолчанию):
  - вытесненный кейкап удаляется сразу, заменяющий появляется на том же месте сразу, без мигания;
  - пока группа видна, её ширина не уменьшается, поэтому центр кейкапа не дрожит при разных подписях;
  - ряд расширяется только для сочетания;
  - отпущенные клавиши прежнего сочетания не переходят в следующее;
  - целиком группа уходит плавно, когда нажатий нет.
- **Политика группировки:** клавиша присоединяется к группе, только если при её нажатии удерживается модификатор. Перекрытие букв при быстрой печати сочетанием не считается (поведение модели 2B, тест `OverlappingLetters_DoNotMergeIntoChord`).
- **Независимые настройки:** след, выдержка и анимация нажатия. Прежний эффект доступен как «Исчезать на месте».
- **Защита сохранена:** устаревшее завершение исчезновения и «оживление» без дублей проверены в обоих режимах.

## 4. Причины: установлено и гипотезы

| Наблюдение владельца | Установлено | Гипотеза |
|---|---|---|
| группа не двигается при центральном якоре | **да**, по коду 2B: отступ сужал полосу симметрично | — |

## 5. Подготовленная ручная проверка (5–10 минут)

### 5.1 Команда запуска

```powershell
dotnet run --project lab/src/KeyOverlay.Lab.App -- --source=raw
```

Чтобы не трогать свои настройки, добавьте `--settings=%TEMP%\keyoverlay-2c\settings.json`. Существующий файл формата 1 будет обновлён автоматически, копия — `settings.v1.bak.json`.

### 5.2 Сценарий

1. **Быстрая печать без следа.** В Блокноте быстро напечатайте «hello world». На оверлее одна клавиша сменяет другую на одном месте; ряд не растёт, кейкап не прыгает по горизонтали между «i» и «w»; после паузы группа плавно исчезает. Наберите Ctrl+S — ряд расширяется до двух клавиш; следующая буква не тянет за собой Ctrl и S.
2. **Раскладка вне ChatGPT.** Откройте окно диагностики рядом.
   - В Блокноте переключите язык сочетанием, затем мышью на панели задач. Повторите в браузере, Проводнике (строка адреса или поиск) и Терминале. Каждый раз должен появиться код языка.
   - Если индикатор молчит, сразу посмотрите строки «Раскладка»: последнее решение, источник HKL, счётчики «поток фокуса ≠ потоку окна» и «HKL фокуса ≠ HKL владельца».
   - Переход между окнами с разными языками должен показывать индикатор, если включено «При переходе в другое окно».
   - При переключении языка в окне настроек KeyOverlay индикатор не появляется.
3. **Обозначения.** «Настройки…» → «Внешний вид»: переключите Windows / macOS / Linux и виды. Превью и оверлей меняются сразу. Нажмите правый Ctrl (метка «R») и Num Enter (метка «num»).
4. **Фильтр.** «Клавиши и сочетания» → «Только сочетания»: печать не показывается, Ctrl+C показывается; удерживая Ctrl, нажмите C ещё раз. Переключитесь обратно на «Все клавиши» — старые буквы не возвращаются.
5. **Положение.** «Положение» → центр (•), «Смещение вправо» −300 — группа уходит влево. Расстояние от края по горизонтали неактивно с пояснением. «Вернуть положение по умолчанию».
6. **Мышь у курсора.** «Мышь» → включить. Значок и круг следуют за указателем; нажатая кнопка зелёная; клики и перетаскивание окон проходят как обычно. Если есть второй монитор с другим масштабом — проведите указатель через границу.
7. **Индикатор во время показа.** «Раскладка» → «Показать индикатор», сразу «Своё» и увеличьте размер текста: индикатор меняется на месте и исчезает в прежний срок.
8. **F1.** В разделе «Мышь» нажмите F1 — справка открывается на разделе «Мышь»; повторный F1 из «Раскладки» использует то же окно.
9. **Перезапуск.** Закройте окно диагностики, запустите снова — настройки сохранены. Сохраните экспорт и, если нужно, приложите его (в нём нет нажатий и окон).

## 6. Оставшиеся ограничения

- **Причина проблемы индикатора** не установлена до ручной проверки. IME-режимы не показываются. Консоль, Терминал, Store-приложения и окна администратора вручную не проверены.
- **Кейкапы:**
  - один стиль lowprofile;
  - нет символов второго ряда, выделения модификаторов, истории, своего списка клавиш, прокрутки и drag;
  - подписи только US;
  - пиксельное сравнение с Keyviz не проводилось.
- **Ширина группы в режиме «без следа»** не уменьшается, пока группа видна. После широкой подписи узкие клавиши стоят по центру более широкой подложки до исчезновения группы — так устраняется дрожание. Решение осознанное, но может потребовать настройки.
- **Мышь у курсора** обновляется таймером ~60 Гц; на мониторах с разным масштабом и при высокой частоте вживую не проверялась. Анимации кольца клика, как у Keyviz, нет.
- **Оверлей** — только основной монитор.
- **Окно настроек:**
  - светлая тема без учёта тёмной темы Windows;
  - доступность для экранного диктора проверена только наличием имён у элементов, не самим диктором.
- **Миграция формата настроек** поддерживает только версию 1 → 2. Файл более новой версии запускается со значениями по умолчанию, копия сохраняется.
