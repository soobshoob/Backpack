# KeyOverlay — приложение и экспериментальный стенд

KeyOverlay показывает нажатые клавиши и кнопки мыши поверх других окон (запись экрана, трансляции, презентации). В одном
исполняемом файле `KeyOverlay.exe` два режима:

- **обычный запуск** — главное окно («Главная», группа «Настройки», «Профили», «Справка», «О программе»), значок в трее,
  оверлей, индикатор раскладки, мышь у курсора, глобальные горячие клавиши, живая линза и временное рисование;
- **стенд** (`--lab`) — прежний режим Phase 1B–2D: окно диагностики при запуске и инструменты проверки (выбор источника,
  `compare`, ёмкость кольца, самопроверка, снимки для справки, сравнительный лист, `--summary-out`). Без `--lab` эти параметры
  не принимаются. Реализация захвата одна и та же.

Этапы: Phase 1B (захват), 2B–2D (визуал, трей, профили, локализация, справка), **2E** (стили, мышь, главное окно, горячие
клавиши, исправление сочетаний), **2F** (живая линза, рисование), **3A** (подготовка выпуска). Отчёты — `lab/docs/`.

Основа: `research/Phase0-Keyviz-Research.md`, `research/Phase1A-Architecture-Refinement.md`, `research/Phase2A-Customization-and-Help-Spec.md`.

## Требования

- Windows 10/11 x64, обычные права пользователя (без повышения прав и без uiAccess).
- Для сборки — .NET SDK 10 (проверено на 10.0.401). Готовый пакет (`tools/package-release.ps1`) — self-contained: ни SDK, ни
  отдельный runtime не нужны.
- Пакеты NuGet только для тестов: xunit 2.9.3, xunit.runner.visualstudio 3.1.4, Microsoft.NET.Test.Sdk 17.14.1, JsonSchema.Net 9.4.1
  (проверка схем `docs/themes/keyoverlay-theme.schema.json`, `docs/settings/*.schema.json`).
- Значок в трее — `NotifyIcon` из Windows Forms в составе .NET. Логотип и иконки — собственная графика
  (`KeyOverlay.Visual/Brand/LogoArt.cs`, исходник `docs/brand/keyoverlay-logo.svg`).
- Шрифт Inter 4.1 (OFL) встроен в сборку `KeyOverlay.Visual`, в системе не устанавливается; происхождение —
  `src/KeyOverlay.Visual/Fonts/README.md`.

## Команды (из корня репозитория)

```powershell
dotnet build lab/KeyOverlay.Lab.slnx
dotnet test  lab/KeyOverlay.Lab.slnx

# обычный запуск (главное окно, трей, горячие клавиши)
dotnet run --project lab/src/KeyOverlay.Lab.App
dotnet run --project lab/src/KeyOverlay.Lab.App -- --minimized      # только значок в трее

# стенд
dotnet run --project lab/src/KeyOverlay.Lab.App -- --lab --source=compare
dotnet run --project lab/src/KeyOverlay.Lab.App -- --lab --source=ll
dotnet run --project lab/src/KeyOverlay.Lab.App -- --lab --demo

# после сборки
lab\src\KeyOverlay.Lab.App\bin\Debug\net10.0-windows\Backpack.exe
lab\src\KeyOverlay.Lab.App\bin\Debug\net10.0-windows\Backpack.exe --lab --source=compare

# пакет выпуска и его проверка (PowerShell 7)
pwsh tools/package-release.ps1 -ReleaseDate 2026-10-30 [-UpdateRepository владелец/репозиторий] [-SkipTests]
pwsh tools/verify-package.ps1  -Zip artifacts/release/Backpack-0.4.0-preview.3-win-x64.zip
```

Параметры:

| Параметр | Режим | Назначение |
|---|---|---|
| `--settings=путь` | оба | другой файл настроек (рядом с ним — `app.json`, `profiles\`, `styles\`) |
| `--minimized` | оба | запуск без главного окна, только значок в трее |
| `--lab` | — | стенд: окно диагностики при запуске и параметры ниже |
| `--source=raw\|ll\|compare` | стенд | источник (по умолчанию `raw`); в `compare` оба источника в своих потоках |
| `--primary=raw\|ll` | стенд | только с `compare`: какой источник питает отображение |
| `--linger-ms=N` | стенд | выдержка после отпускания только на этот запуск |
| `--ring=N` | стенд | ёмкость кольца событий (степень двойки); `--ring=8` — воспроизвести переполнение |
| `--demo` | стенд | пример на оверлее (13 с) и индикатор «EN» |
| `--selftest-ui` | стенд | самопроверка окон без ввода (разделы × 3 языка × 2 темы, справка, трей, показ/скрытие отображения, статусы горячих клавиш, проба линзы), затем выход; итог — `ShutdownNotes` |
| `--render-help-images=папка` | стенд | снимки собственных окон для `docs/help/images` |
| `--render-brand=папка` | стенд | логотип: SVG, ICO приложения и трея, PNG на светлой/тёмной панели |
| `--render-sheet=папка` | стенд | сравнительный лист рендеров кейкапов и мыши (`docs/review/phase2e`) |
| `--auto-exit-ms=N` | стенд | закрыть через N мс (с самопроверкой стилей окон) |
| `--summary-out=путь` | стенд | после завершения записать агрегированный JSON |
| `--privacy-trace=путь` | стенд | журнал приватности: время, версия контекста, состояние, причина, число показанных кейкапов (без клавиш) |

## Данные

- Папка: `%APPDATA%\Backpack` (`settings.json` формата 7, `app.json` формата 4, `profiles\` формата 3 — автосохранение, `styles\`).
- Portable: файл `KeyOverlay.portable` рядом с `KeyOverlay.exe` → папка `Data` рядом с программой, если в неё можно писать
  (иначе — `%APPDATA%\KeyOverlay` и сообщение при запуске).
- Перенос: при первом запуске без настроек в новой папке копируются `settings.json`, `app.json` и `profiles\*.json` из
  `%APPDATA%\KeyOverlay.Lab` (существующие файлы не перезаписываются, исходные не удаляются). Старые форматы читаются с
  миграцией; исходный файл сохраняется копией `settings.v1.bak.json` / `settings.v2.bak.json` перед первой записью.
- Глобальные горячие клавиши, язык, тема, трей, линза, рисование и обновления — `app.json` (этот компьютер); в профиль не входят.

## Что на экране (обычный режим)

- **Главное окно.** Навигация: «Главная» (отображение, профиль, быстрые переключатели, линза и рисование), «Настройки» —
  раскрывающаяся группа (Внешний вид, Клавиши и сочетания, Мышь, Раскладка, Положение, Горячие клавиши, Приложение, Справка и
  диагностика), «Профили», «Справка», «О программе». Превью закреплено над областью прокрутки; их границы не пересекаются, при
  прокрутке видна линия края, высота превью подстраивается под окно. × главного окна по умолчанию прячет его в трей.
- **Каталоги стилей** кейкапов, индикатора и мыши: миниатюры настоящим рендером, выбранное состояние, отметка «изменён»,
  сохранить / как новый / дублировать / переименовать / удалить / восстановить / импорт / экспорт / папка стилей.
- **Рендеры кейкапов:** lowprofile, laptop, pbt, minimal (собственный WPF-код по формулам из кода Keyviz, Phase 2A) и
  объёмный (вид спереди-сверху, Г-образный Enter). **Мышь:** контурный, сплошной, ретро, скетч; боковые кнопки (ручная
  настройка); стрелка прокрутки.
- **Горячие клавиши** (по умолчанию Ctrl+Alt+Shift+O/Z/D/R): показ/скрытие, линза, рисование, радиальное меню.
- **Живая линза** (Magnification API) и **рисование** (окно режима принимает мышь, только пока режим активен).
- **Значок в трее:** щелчок — главное окно; меню — «Открыть KeyOverlay», показ отображения, быстрые переключатели, профиль,
  справка, выход.
- **Справка** — `docs/help/<uk|en|ru>/*.md` (14 страниц) и `docs/help/images/`, встроенные в сборку; F1 локальна.

## Устройство (кратко)

```
Поток RawInput (message-only окно, WM_INPUT)   ┐   CaptureState: таблица наблюдавшихся состояний + SPSC-кольцо
Поток LL-хука  (WH_KEYBOARD_LL, WH_MOUSE_LL)   ┘   (каждым владеет только свой поток; снимок строится в нём же)
        │ Dispatcher.BeginInvoke(Input) — без ожидания; резервный опрос 100 мс
        ▼
UI-поток: SourceReader → SourceModel (Up/Down/Unknown, asOf; импульсы колеса — отдельно, не состояние)
          → DisplayModel (Id записи, выдержка, правило объединения) → OverlayWindow
          сверка GetAsyncKeyState (только основной источник), проверки здоровья, экспорт
          OverlayWindow → KeyOverlay.Visual: OverlayPresenter → KeycapControl (5 рендеров; анимации по CompositionTarget.Rendering,
          только пока они идут); импульсы колеса → MouseCursorController; Esc (только наблюдение) → инструменты презентации
HotkeyManager (RegisterHotKey, MOD_NOREPEAT, свой message-only HWND) → показ/скрытие, линза, рисование, радиальное меню
```

Проекты:

| Проект | Содержимое | Зависимости |
|---|---|---|
| `KeyOverlay.Lab.Core` | события (в т. ч. колесо), транспорт, модели, диагностика | — |
| `KeyOverlay.Lab.Win32` | Raw Input, LL-хуки, зонды, стили окна оверлея | Core |
| `KeyOverlay.Visual` | рендеры кейкапов и мыши, презентер, фильтр, стили, главное окно, индикатор, мышь у курсора, справка, горячие клавиши, линза, рисование, обновления, логотип | только WPF (не зависит от захвата и App) |
| `KeyOverlay.Lab.App` (`KeyOverlay.exe`) | приложение и стенд | Core, Win32, Visual |

- **Протокол ресинхронизации.** У каждого события — номер последовательности источника. При переполнении кольца событие
  отбрасывается, растёт «эпоха потерь». Получатель запрашивает снимок; поток источника строит его между событиями. Снимок с
  номером S применяется раньше кольца; события ≤ S повторно не применяются. Колесо получает номер, но в таблицу удержания не
  входит: снимок его не «восстанавливает», потерянный при переполнении импульс не воспроизводится.
- **Unknown.** Блокировка/разблокировка, смена рабочего стола, пробуждение переводят нажатые клавиши основного источника в
  Unknown (не в Up). Unknown не формирует сочетание и уходит по выдержке. Те же события закрывают линзу и рисование.
- **Сверка (эвристика).** Только при доверенном контексте и положительном контроле; см. Phase 1A.
- **Восстановление.** Источники автоматически не переустанавливаются никогда; окно оверлея — только по подтверждённой потере.

### Задержки (определения)

| Метрика | От | До |
|---|---|---|
| LL callback | вход в callback | перед `CallNextHookEx` |
| Raw Input message | вход в обработчик `WM_INPUT` | выход |
| capture → model | получение события потоком захвата | применение к модели в UI-потоке |
| model → UI apply | изменение модели отображения | обновление свойств оверлея в UI-потоке |

Время до видимого пикселя не измеряется.

## Ручной сценарий захвата (стенд, 5–10 минут)

Запустите `KeyOverlay.exe --lab --source=compare`, откройте Блокнот рядом. Тот же чек-лист показан в окне диагностики.

1. Печатайте в Блокноте — фокус не уходит на оверлей.
2. Кликните по кейкапу на оверлее — клик доходит до окна под ним.
3. A: нажать/отпустить — появляется, гаснет через выдержку.
4. Удерживать A 3 с — один нажатый кейкап без бейджа; растёт `повторы`.
5. Ctrl+Shift+K → «Ctrl Shift K» с пометками L; отпустить K и нажать снова, не отпуская модификаторы → бейдж «2» у K.
6. Левые/правые Shift/Ctrl/Alt — разные пометки L/R; Enter и Num Enter — разные (пометка Num).
7. Быстрая печать с перекрытием — буквы не склеиваются в «сочетание».
8. Alt+Tab — оверлея нет в списке и на панели задач.
9. «Скрыть оверлей», подождать 5 с — оверлей не возвращается сам; «Показать оверлей» возвращает.
10. «Экспорт…» — в файле только числа, флаги, коды находок и определения метрик.
11. Перезапуск с `--lab --source=compare --ring=8`: «Заморозить UI на 3 с», во время заморозки напечатать слово и отпустить все
    клавиши. После разморозки: `эпоха потерь` > 0, ресинхронизация выполнена, `сейчас нажато` = 0, залипших кейкапов нет.

Сценарии визуальных этапов — `lab/docs/Phase2B…2D`, новые — `Phase2E-Implementation-Report.md` (§ ручная проверка, включая
Win-сочетания в `compare`), `Phase2F-Implementation-Report.md`, `Phase3A-Release-Readiness-Report.md`.

## Данные и приватность

- Коды клавиш, события и импульсы колеса существуют **только в памяти**.
- На диск пишется: экспорт по кнопке или `--summary-out` (только агрегаты: счётчики, перцентили, флаги, коды находок, в том числе
  число импульсов колеса и сочетаний с модификатором/Win по источникам — без клавиш и порядка), `settings.json`, `app.json`,
  `profiles\`, `styles\` (параметры оформления, поведения, положения; горячие клавиши — как сочетания команд). Набранного
  текста, кодов клавиш, последовательностей, координат указателя и содержимого экрана там нет; для экспорта это проверяет тест
  `ExportContainsOnlyAggregateFields_AndNoKeyIdentities`.
- Линза получает изображение экрана от системы в памяти (Magnification API) и ничего не сохраняет и не передаёт; рисунки не
  сохраняются.
- Сетевое обращение одно: проверка обновлений GitHub Releases — по кнопке или раз в сутки, если включено; только GET списка
  выпусков. Пока репозиторий не задан, обращений нет.

## Чего KeyOverlay сознательно не делает

Блокировку, UAC, сон, перезапуск Explorer, смену DPI, инжекцию ввода и искусственное торможение глобального хука программа сама
не выполняет. Нет uiAccess и повышения прав, нет скрытой загрузки и запуска обновлений, нет автозапуска.
